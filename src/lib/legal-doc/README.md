# legal-doc — เอกสารรูปแบบจริงสำหรับข้อสอบ

พิมพ์เอกสารกฎหมายใหม่เป็น **ข้อความจริง** โดยจัดหน้าเลียนต้นฉบับ สำหรับข้อสอบ
๓ กรณี: เอกสารในโจทย์ (`stimulus`), ธงคำตอบที่ตัวมันเองเป็นเอกสาร (`model-answer`),
และแบบฟอร์มเปล่าไว้ฝึกร่าง (`blank-form`)

## กติกาเหล็ก: อะไรอยู่ที่ไหน

```
legal-doc/
  ir.ts            zod schema — สัญญากลางระหว่าง CLI, renderer และเว็บ
  thai.ts          grapheme/word segmentation, เลขไทย
  render/          เรนเดอร์ IR → PDF
  node/            ⚠ เฉพาะไฟล์ในนี้ที่แตะ Node API ได้
```

**ทุกไฟล์นอก `node/` ห้าม import `fs`, `child_process`, `sharp`, `pdf-to-img`**
เหตุผล: renderer ตัวเดียวกันต้องรันได้ทั้งใน CLI, ใน server action ของ Next
และใน Cloudflare Worker ตอนยกขึ้นเว็บ โดยไม่ต้องย้ายไฟล์หรือ fork โค้ด
ทรัพยากรภายนอก (ฟอนต์, ตราครุฑ) ส่งเข้ามาเป็น `AssetBundle` ของ byte เสมอ

## ระบบพิกัด

IR ใช้ **จุด (pt) origin ซ้ายบน y เพิ่มลงล่าง** ซึ่งตรงกับวิธีที่คนอ่านเอกสาร
pdf-lib ใช้ origin ซ้ายล่าง การกลับด้านเกิดขึ้นที่ `render/draw.ts` → `flipY()`
**ที่เดียว** อย่ากลับด้านซ้ำที่อื่น

## สองเรื่องที่ต้องไม่ทำพลาด

### ๑. ห้ามใช้ `page.drawText()`

pdf-lib ทิ้ง GPOS — `CustomFontEmbedder.encodeText()` เก็บแค่ `layout().glyphs`
แล้วทิ้ง `layout().positions` ผลคือวรรณยุกต์บนพยัญชนะสูงลอยไปอยู่ขวา
วัดกับ Sarabun: `ปั้` ต้องเลื่อน −163/1000 em แนวนอน −32 แนวตั้ง
ที่ 16pt คือ 2.6pt ซึ่งเห็นชัด (เทียบภาพได้ที่ `out/gpos2.png`)

ใช้ `render/draw.ts` → `drawText()` / `drawShapedText()` แทน **รวมถึงข้อความ
ท้ายหน้าและทุกอย่างที่เล็กจนคิดว่าไม่สำคัญ**

### ๒. ห้ามใช้ `PDFFont.widthOfTextAtSize()`

มันบวก `glyph.advanceWidth` จาก hmtx โดยไม่สน GPOS ถ้าวัดด้วยตัวหนึ่งแต่วาด
ด้วยอีกตัว การจัดกึ่งกลาง ชิดขวา และเส้นนำสายตาจะเพี้ยนสะสม
ใช้ `render/shaper.ts` → `measureText()`

## ข้อจำกัดที่รู้อยู่: หางสระอำ

ฟอนต์แตก `ำ` เป็นนิคหิต (ToUnicode ชี้ไป `ำ` ครบแล้ว) ตามด้วย glyph `า`
ที่เป็นแค่รูปร่าง ไม่มีความหมาย — และเป็น **glyph ตัวเดียวกับ `า` เดี่ยว**
ToUnicode เป็น map หนึ่ง glyph ต่อหนึ่งความหมาย จึงให้ glyph นั้นเป็นทั้ง
"ว่าง" และ "า" พร้อมกันไม่ได้

เราแก้โดยฝังฟอนต์ไฟล์เดิมสองชุด ชุด `tail` ใช้วาดเฉพาะหางสระอำ ToUnicode
ของมันจึงว่างได้ถูกต้อง (ดูรายละเอียดเต็มในหัวไฟล์ `render/shaper.ts`)

ผลที่เหลือ: pdfjs เลือกคืนรหัส glyph ดิบเป็นอักขระควบคุมแทนที่จะข้ามไป
ข้อความจึงถูกทุกตัวอักษร แต่มีอักขระควบคุมที่มองไม่เห็นแทรกหลัง `ำ`
ทางแก้ตามสเปกคือ ActualText marked content แต่ pdfjs ไม่รองรับเลย
`scripts/legal-doc/cli.ts` จึงรายงานจำนวน artifact นี้แยกออกมาตอน verify

**อย่าแก้ด้วยการใช้ glyph `ำ` แบบรวมร่าง (id 489)** — มันจะทำให้คำที่มี
วรรณยุกต์ควบอย่าง `น้ำ` `ค้ำ` `ย้ำ` วางวรรณยุกต์ผิด เพราะฟอนต์มี glyph
เฉพาะสำหรับ `้ำ` อยู่แล้ว

## อย่าเชื่อ `glyph.codePoints`

fontkit แคช `Glyph` object ตาม glyph id ต่อหนึ่ง font instance ค่า `codePoints`
จึงขึ้นอยู่กับว่า glyph นั้นถูกสร้างครั้งแรกจากทางไหน — คือขึ้นกับ **ลำดับ
ข้อความในเอกสาร** `render/fonts.ts` จึง warm แคชด้วย `า` เดี่ยวก่อนอย่างอื่น
เพื่อล็อกผลให้แน่นอน

## ใช้งาน

```bash
npm run legal-doc -- build docs/legal-doc/<ชื่อ>.json -o out/<ชื่อ>.pdf
npm run legal-doc -- preview out/<ชื่อ>.pdf --dpi 150
npm run legal-doc -- verify out/<ชื่อ>.pdf --ir docs/legal-doc/<ชื่อ>.json
```

`build` เรียก `verify` ให้เองเสมอ ซึ่งตรวจสองอย่าง: round-trip ข้อความ
(พิสูจน์ว่า ToUnicode ไม่พัง จึงค้นหา/คัดลอกได้) และ **ลำดับตัวเลขต้องตรงเป๊ะ**
— ในข้อสอบตั๋วเงิน จำนวนเงินหรือวันที่ผิดตัวเดียว คำตอบเปลี่ยน
